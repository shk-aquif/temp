PRACTICAL NO. 1
--------------------------------------------------------------------------------
Aim: 
Introduction to Wireless Sensor Networks (WSN). Study the basic components, 
working, and applications of a Wireless Sensor Network.

Required Tools / Devices:
- Computer or laptop
- Notebook / journal

Procedure / Steps:
1. Study the meaning of a Wireless Sensor Network (WSN). A WSN is a group of small sensor nodes that collect information from the surrounding environment and send it to a base station.
2. Identify the main components: sensor nodes, a sink or base station, a gateway, and a monitoring computer or user.
3. Study the working process. Sensor nodes sense information such as temperature, movement, or light and send the collected data wirelessly to the sink or base station.
4. Study the role of the gateway. It can connect the sensor network to another network or to the Internet.
5. Write down common applications such as environmental monitoring, agriculture, healthcare, smart homes, and industrial monitoring.
6. Note the main challenges of WSNs, including limited battery power, limited memory, communication range, security, and reliable data transmission.

Result:
The basic components, working, applications, and challenges of a Wireless Sensor Network were studied.

PRACTICAL NO. 2
--------------------------------------------------------------------------------
Aim: 
Sensor Mote and Base Station Communication Study. Develop a simple communication 
scenario between sensor motes and a base station to study data collection and 
device control.

Required Tools / Devices:
- Cisco Packet Tracer
- Home Gateway (1)
- Smartphone (1)
- Motion Detector, Garage Door, Ceiling Fan, and Light

Procedure / Steps:
1. Open Cisco Packet Tracer.
2. From Network Devices, place one Home Gateway in the workspace.
3. From End Devices, place a Smartphone, Motion Detector, Garage Door, Ceiling Fan, and Light.
4. Click each IoT device. Open Config -> Settings (Global). Under IoT Server, select Home Gateway. Repeat for all IoT devices.
5. Click the Smartphone. Open Config -> Wireless0 and change the SSID from Default to HomeGateway. Check that it connects to the Home Gateway.
6. Click the Home Gateway and open Config -> LAN. Note its IPv4 address (often 192.168.25.1). Use the address shown in your simulation.
7. On the Smartphone, open Desktop -> Web Browser. Enter the Home Gateway IP address and press Go. Sign in with the default credentials shown by Packet Tracer (commonly admin / admin).
8. Open the Conditions tab and add a rule. For example: If Motion Detector is on, then turn the Light on, set the Ceiling Fan to Low or High, and open the Garage Door. Save the rule.
9. Hold Alt and hover over the Motion Detector to simulate motion. Check whether the configured devices respond.

Result:
The IoT devices were registered with the Home Gateway and an automation rule was tested.

PRACTICAL NO. 3
--------------------------------------------------------------------------------
Aim: 
Creation of a Simple Ad-hoc Network Using TOSSIM. Create a multi-node wireless 
network and observe broadcast communication among nodes.

Required Tools / Devices:
- Cisco Packet Tracer
- WRT300N wireless router (1)
- PC-PT computers (5)
- PT-HOST-NM-1W wireless module for each PC

Procedure / Steps:
1. Open Cisco Packet Tracer. Place one WRT300N wireless router and five PCs (PC0 to PC4) on the workspace.
2. For each PC, open Physical. Turn the power off, remove the FastEthernet module (PT-HOST-NM-1CFE), insert the PT-HOST-NM-1W wireless module, and turn the power on again.
3. Repeat the module installation for all five PCs.
4. Wait for the wireless connections to appear. The router and PCs normally use the Default SSID.
5. Switch to Simulation mode. Click Show All/None, then Edit Filters. Under IPv4, select ICMP and ARP.
6. Open PC0 -> Desktop -> Command Prompt.
7. Enter ping 192.168.0.255 to attempt broadcast communication with nodes on the subnet.

Result:
A wireless multi-node network was created and broadcast communication was observed in Simulation mode.

PRACTICAL NO. 4
--------------------------------------------------------------------------------
Aim: 
Mote-to-Mote Radio Communication Simulation. Simulate packet transmission between 
wireless nodes and check communication using ping.

Required Tools / Devices:
- Cisco Packet Tracer
- WRT300N router
- Laptop, Smartphone, and Tablet

Procedure / Steps:
1. Open Cisco Packet Tracer and place a WRT300N router, one Laptop, one Smartphone, and one Tablet.
2. Click the Laptop -> Physical. Turn the laptop off, install the PT-LAPTOP-NM-1W wireless module, and turn it on again.
3. Check the router's network settings if needed.
4. Open Desktop -> IP Configuration on the Laptop and choose Static. Set the IP address to 192.168.0.2.
5. Set the Tablet's static IP address to 192.168.0.3.
6. Set the Smartphone's static IP address to 192.168.0.4. Use suitable subnet masks for the same network.
7. On the Laptop, open Desktop -> Command Prompt and enter ping 192.168.0.3.
8. Check whether the Tablet replies to the ping.

Result:
Wireless nodes were configured with IP addresses and connectivity was tested using ping.

PRACTICAL NO. 5
--------------------------------------------------------------------------------
Aim: 
Routing Table Generation and Analysis in WSN. Build a small routed network and 
observe routing table updates.

Required Tools / Devices:
- Cisco Packet Tracer
- 3 Cisco 1841 routers
- 3 Cisco 2960 switches
- 9 PCs
- WIC-2T modules
- Automatic connection cable and Serial DCE/DTE cable

Procedure / Steps:
1. Place three Cisco 1841 routers (R0, R1, R2), three Cisco 2960 switches (SW0, SW1, SW2), and nine PCs (PC0 to PC8). Group three PCs near each switch.
2. For each router, open Physical, turn the power off, insert a WIC-2T module, and turn the power on.
3. Connect PC0-PC2 to SW0 and SW0 to R0. Connect PC3-PC5 to SW1 and SW1 to R1. Connect PC6-PC8 to SW2 and SW2 to R2 using the automatic connection cable.
4. Connect the routers to one another using Serial DCE/DTE cables, following the topology in the journal.
5. Configure suitable IP addresses and subnet masks on all PC network interfaces.
6. Configure IP addresses on the router LAN and serial interfaces. Enable the interfaces using the appropriate interface configuration commands.
7. Configure RIP routing on the routers and advertise the connected networks.
8. Use the show ip route command on each router to view the routing table.
9. Test connectivity between PCs on different networks using ping.

Result:
The routers were configured and their routing tables and inter-network connectivity were checked.

PRACTICAL NO. 6
--------------------------------------------------------------------------------
Aim: 
Mote-to-PC Serial Communication Using OMNeT++. Simulate a sensor mote sending 
readings to a PC module.

Required Tools / Devices:
- OMNeT++ IDE
- A new OMNeT++ project
- NED network file and C++ simple modules

Procedure / Steps:
1. Open OMNeT++ and create a new project named MoteSerialComm.
2. Create a NED network file named MotePCSerial.ned and define a Mote module connected to a PC module through a serial-style connection.
3. Create the Mote C++ files (Mote.h and Mote.cpp). The mote should generate a reading periodically and send it through its output gate.
4. Create the PC C++ files (PC.h and PC.cpp). The PC module should receive each message and print it in the simulation log.
5. Create or update omnetpp.ini to select the network and configure the simulation.
6. Build the project. Fix any compilation errors before running it.
7. Run the simulation and check the output log for messages sent by the mote and received by the PC.

Result:
The OMNeT++ simulation was used to demonstrate sensor-reading messages being sent from a mote module to a PC module.

The wireless network was configured and communication between the connected devices was tested.

- Cell Tower
- Central Office Server
